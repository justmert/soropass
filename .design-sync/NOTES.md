# design-sync notes — @soropass/ui-react → Claude Design

## What this DS is

- The synced package `@soropass/ui-react` is a **net-new React adapter**, not the real UI. The real SoroPass UI is `@soropass/ui` (framework-agnostic, plain-DOM `mountX` / `*View` functions returning `HTMLElement`). Claude Design is React-only, so the adapter wraps each styled `*View` in a React component (`useRef` + `useEffect` + `replaceChildren`). Five screens: Create / Sign / Recover / Connect / AddDevice.
- Production apps should use `@soropass/ui` directly; `ui-react` exists to feed design-sync.

## Build / run gotchas

- **buildCmd**: `pnpm --filter "@soropass/ui-react..." build` — the trailing `...` builds `@soropass/core` + `@soropass/ui` (deps) before `ui-react`. Bare `-F @soropass/ui-react` skips deps and the dts build fails to resolve `@soropass/ui/*`.
- **CSS lives in a sibling package.** The real stylesheet is `@soropass/ui` `styled/tokens.css` + `styled/passkey.css`. `cfg.cssEntry` is hard-bounded to the DS package dir, so pointing it cross-package is rejected. The `ui-react` build runs `scripts/bundle-css.mjs`, which concatenates those two files into `packages/ui-react/styles.css` (self-contained, no `@import`/`url()`), and `cssEntry` points at that. `styles.css` is gitignored and regenerated by buildCmd — so a token change in `@soropass/ui` flows in on the next build.
- **--node-modules** = `./packages/ui-react/node_modules` (pnpm symlinks `react`, `react-dom`, `@types/react`, `@soropass/*` there).
- **--entry** = `./packages/ui-react/dist/index.js`.
- **Playwright**: chromium is cached at `~/Library/Caches/ms-playwright/chromium-1223` (macOS path — NOT `~/.cache`), matching `playwright-core@1.60.0`. `package-validate.mjs` needs `playwright` importable from the staged scripts, so install it INTO `.ds-sync`: `(cd .ds-sync && npm i playwright@1.60.0)`. It is not resolvable from the repo root.

## Authoring gotchas (learned this run)

- **Grouping via `@category`**: all 5 components live in one `src/index.tsx`. `leadingJsdoc` only picks up the JSDoc that sits **directly above `export function <Name>`** — if the `interface <Name>Props` (with its own prop JSDoc) sits between the doc and the function, it returns empty and the component drops to group `general` with no description. Keep the rich `/** … @category Passkey */` block immediately above each `export function`; give the interface a short separate doc. Group is `passkey`.
- **Preview example comments leak**: a leading `/** … */` on a preview export gets captured into the **previous** export's `.prompt.md` example block. Keep `.design-sync/previews/*.tsx` exports comment-free; the export name is the cell label.
- `@category Passkey` prints verbatim in each `.prompt.md` description (minor JSDoc blemish — acceptable, not worth a lib override).

## Re-sync risks (what a future sync should watch)

- **`styles.css` is generated**, not committed. If someone edits it by hand it will be overwritten on the next build. Real styling changes belong in `@soropass/ui`'s `styled/tokens.css` / `passkey.css`.
- **Adapter is coupled to `@soropass/ui` view signatures**: `createView` / `signView` / `recoverView` / `connectView` / `addDeviceView` and the `DEFAULT_*_COPY` exports, plus the flow-state unions from `@soropass/ui/headless` and `RecoverResult` from `@soropass/core/recover`. If `@soropass/ui` renames or reshapes any of these, `packages/ui-react/src/index.tsx` must be updated or the build breaks.
- Preview state objects (contract addresses, tx hash, credential ids) are **illustrative fixtures** inlined in the preview `.tsx` — they don't track real chain data, which is correct for rendering but means they won't "go stale" against chain state.
- Grades are carried by `_ds_sync.json` in the uploaded project (verification anchor); the local `.cache/` is gitignored.
